# Снежный переполох: переработка интерфейса, 27.11.2026

## Изменения

- `src/pages/SnowEvent.tsx`: отдельные композиции анонса, декабря, январского магазина и завершённого события. В декабре игра идёт перед кошельком, календарём, станцией и магазином. По времени сервера страница обновляется также на каждой московской полуночи.
- `src/components/snow-event/SnowEventSections.tsx`: адаптивный заголовок в две строки, компактный активный баннер, единый таймер; четыре особенности события вместо большого игрового интерфейса до старта; календарь с понедельником перед 1 декабря (вторник), недельный прогресс; станция с этапами 0/25/50/75/100%; магазин с горизонтальными карточками на телефоне.
- `SnowRewardArt.tsx`: собственные SVG-иллюстрации значка, оформления профиля, кристалла трафика и подарков с часами. Исходные WebP с котом сохранены без изменения.
- `SnowEventControls.tsx`: выделены настоящие административные настройки предпросмотра и подтверждение обмена. Ключ операции обмена сохраняется при фоновых обновлениях и повторе после ошибки сети.
- `SnowGame.tsx`: игра в отдельном окне, которое помещается на 320×568; повтор неудачной попытки после серверного интервала, защита от повторной отправки, очистка таймеров и один стабильный обработчик клавиатуры. Все попадания и начисления по-прежнему проверяет API.
- `snowPresentation.ts` и тесты: доступность наград, реальный статус `sync_pending`, недельные окна, московские границы суток. Цены и описания подарков приходят из API.
- `snow-experience.css`: оформление изолировано корневым классом события и классами его диалогов. Общие страницы, меню, профильные награды и старые общие стили не редактировались.
- `scripts/xsg-deploy-cabinet.sh`: самостоятельный деплой только фронтенда с сохранением работающего образа, файлов сайта, конфигурации и исходников; предварительным HTTP probe и автоматическим откатом.

Кошелёк различает текущий баланс и накопленный вклад. Показатель «сегодня» включает ежедневный визит и игру (из 15); недельный бонус показан отдельно, поскольку API не сообщает дату его получения. Покупки не уменьшают накопленный вклад.

## Проверки

Проверялся настоящий `SnowEvent` внутри `AppShell`, с настоящими компонентами, FastAPI-маршрутами события и SQLite. Авторизация локального стенда подменена тестовыми заголовками; производственные аккаунты, подписки и балансы не использовались.

Chrome/Playwright: **42 сценария**:

- Анонс и активный декабрь на 320×568, 375×667, 390×844, 430×932, 440×956, 1280×800, 1440×900 и 1920×1080. Проверены не только scrollWidth документа, но границы заголовков/текста/кнопок, первая календарная неделя и число колонок магазина. Полноразмерные снимки сохранены и просмотрены, в том числе сводные листы всех восьми размеров.
- Нет подписки, истекла, продлена, магазин января, завершение и доступные подарки на 390 и 1440 px.
- На 320×568: ежедневный подарок, настоящая 20-секундная игра с серверными попаданиями, получение награды, обмен, состояние «получено», истечение и продление с сохранением прогресса. Проверена полная видимость игрового диалога в окне.
- Все пять этапов станции. Частичный календарь и недельные отметки загружались через настоящий API из изолированной таблицы предпросмотра локального стенда.
- Длинные названия/описания и большие числа на 320 px — синтетические данные только для проверки вёрстки.
- Искусственный HTTP503 при обмене, понятная ошибка, повтор после фонового обновления с тем же request_id, единственная выдача подарка.
- Анонс без подписки с раскрытыми правилами и каталогом; существующий административный экран.
- Автоматический переход 30 ноября → 1 декабря по времени API при намеренно неправильном `Date.now()` браузера.
- Переключение дат через реальные настройки предпросмотра (30 ноября, 1/31 декабря, 1/8 января) и сброс прогресса с подтверждением.
- Главная на 390 и 1440 px: подключение/удаление нового CSS не меняет размеры и текст страницы. Существующая маршрутизация нижней навигации сохранена; шестая кнопка не добавлялась.

Дополнительно сняты первые экраны обычного пользователя на 390×844 для анонса и активного дня. Основная кнопка игры видна без прокрутки. Веб-шрифт Manrope в стенде обслуживался локально из тех же файлов Google Fonts: первоначальная блокировка внешнего домена была ограничением тестового браузера, а не ошибкой React.

Итоговые журналы браузера: нет ошибок JavaScript/React и неожиданных сетевых ошибок. Ожидаемый HTTP503 из проверки повтора записан отдельно. Консоль реального пользовательского браузера в этом поручении не предоставлялась, поэтому его возможным расширениям/ошибкам причины не приписывались.

Автоматические проверки: TypeScript; Biome изменённых компонентов и формат CSS; production-сборка Vite; 4 новых теста представления; 26 серверных тестов события, изоляции и выдачи; 6 тестов готовности реальным curl (TCP reset и постоянный HTTP503); 4 теста настоящего nginx 1.30.8, включая production dist, SPA-маршрут и доступность картинок; `sh -n` нового деплоя; `git diff --check`.

Материалы локальной проверки: `bedolaga-context/verification/snow-event-polish/` — `results.json`, `extra-results.json`, `controls-results.json`, скрипты и PNG. В production они не попадают.

## Деплой и откат

Скрипт обновляет только кабинет. Существующие API/БД события не заменяются и не откатываются. До замены контейнера проверяется наличие маршрута API, сборка, `nginx -t`, отдача SPA и картинки из отдельного контейнера. После замены проверяется готовность и совпадение публичных JS/CSS с запущенным контейнером. При ошибке после замены возвращается сохранённый образ.

На сервере:

```bash
cd /home/user1/bedolaga-cabinet
sudo git -c safe.directory="$PWD" fetch https://github.com/XSGGH/bedolaga-cabinet.git xsg-theme
sudo git -c safe.directory="$PWD" show FETCH_HEAD:scripts/xsg-deploy-cabinet.sh | sudo tee /root/xsg-deploy-cabinet.sh >/dev/null
sudo bash /root/xsg-deploy-cabinet.sh </dev/null
```

Откат последнего успешного обновления:

```bash
backup=$(sudo cat /root/bedolaga-cabinet-backups/last-backup)
sudo bash "$backup/deploy-script.sh" --rollback "$backup" </dev/null
```

Скрипт также печатает точную команду отката для созданного им бэкапа ещё до сборки. Локальный `nginx.conf` и `docker-compose.override.yml` сохраняются. Отсутствующий исходный image ID обрабатывается через сохранение работающего контейнера. Никакого `git reset --hard`, force push или восстановления старой БД.

Если API события ещё не установлен после предыдущего отката, новый скрипт остановится до замены frontend. Установку/продолжение исходной API-надстройки выполняют отдельные `xsg-deploy-snow.sh` / `xsg-resume-snow.sh`, описанные в `snow-event-2026.md`; графическую переработку не следует использовать как повод вслепую повторять миграции или подменять ветку бота.

Docker и SSH к production в локальном стенде недоступны. Полный запуск Docker-деплоя на сервере не заявляется проверенным: проверены синтаксис, HTTP-политика повторов и production dist настоящим локальным nginx. После серверного запуска следует открыть `/admin/snow-event` и пройти нужный сценарий предпросмотра.
