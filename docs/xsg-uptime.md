# Статус серверов XSG: подключение и обновление

Блок работает с авторизованным API `https://uptime.xsgvpn.ru/api/public`.
Контракт: https://github.com/XSGGH/xsg-statuspage/blob/main/API.md

Браузер вызывает только фиксированные маршруты `GET /status-api/public`, `/status-api/summary` и `/status-api/events` на домене кабинета. Nginx контейнера добавляет серверный ключ; произвольные API-пути, включая административные, через этот proxy недоступны. Для каждого маршрута отдельный общий кэш успешного ответа на 30 секунд, проверка TLS upstream и тайм-ауты. Ошибка обновления не заменяется устаревшим кэшем. Сводки опрашиваются раз в минуту, события загружаются при раскрытии подробностей. Ключ и cookies браузером не отправляются.

Модель `serverStatusModel.ts` использует текущие `online`/`maintenance`, а не исторический uptime или нагрузку. Подтверждённое обслуживание имеет отдельный янтарный статус. Частично работающая группа определяется по `membersOnline/members` из `summary`; детали другой генерации с противоречащими флагами не смешиваются с основной сводкой. Приоритет: недоступность → нестабильность → отсутствие данных → обслуживание → штатная работа. Счётчик относится к показанным VPN-направлениям: API `totals` также может учитывать сайты, а обслуживание исключает из своих totals. Мобильные проверки независимы. Ошибка основной сводки убирает прежний зелёный статус; недоступность дополнительных данных не выдаётся за отказ VPN. История строится по типам событий и подтверждённым временам начала/окончания, без распознавания статуса по тексту заголовка.

При обновлении нужен новый `nginx.conf` с тремя разрешёнными маршрутами. Локальные изменения серверной конфигурации следует совместить с ним; не заменять весь файл старой копией после обновления. Если дополнительный маршрут не настроен, основная сводка продолжит работать, но детализация групп и история недоступны.

Ключ задаётся **только** в `.env` кабинета: `XSG_UPTIME_API_KEY`. Его передаёт `env_file` в compose. На старте официального образа Nginx envsubst формирует конфигурацию из `nginx.conf`; подстановка ограничена этой одной переменной. Пустой ключ отключает proxy (503), остальные страницы кабинета работают. `.env` исключён из Git и Docker build context. Не использовать `VITE_*`, build args или ключ в URL.

## Обновление существующего Docker-кабинета

Применимо к установке в `/home/user1/bedolaga-cabinet`, ветке `xsg-theme` и remote `xsg`, указывающему на XSGGH. Перед началом проверить `git status -sb` и `git remote -v`. Если есть локальные изменения, сохранить/разобрать их; команды ниже не используют принудительный reset.

Сначала резервная копия текущего checkout и настроек (в архив попадут секреты из `.env`, поэтому хранить только на сервере):

```bash
cd /home/user1/bedolaga-cabinet
umask 077
mkdir -p "$HOME/bedolaga-cabinet-backups"
tar --exclude=./node_modules --exclude=./dist --exclude=./.git -czf "$HOME/bedolaga-cabinet-backups/cabinet-$(date +%Y%m%d-%H%M%S).tar.gz" .
git rev-parse HEAD > "$HOME/bedolaga-cabinet-backups/previous-commit.txt"
git fetch xsg xsg-theme
git merge --ff-only xsg/xsg-theme
```

Задать ключ интерактивно: он не выводится в терминал и не записывается в историю команд. Скрипт дополнительно копирует `.env` и compose в закрытый каталог `$HOME/bedolaga-cabinet-backups/DATE/`.

```bash
bash scripts/configure-uptime.sh
docker compose up -d --build cabinet-frontend
```

Ключ вставлять без кавычек, пробелов и обратного слеша. Скрипт проверит формат, заменит прежнюю строку `XSG_UPTIME_API_KEY`, остальные настройки сохранит. Бот не требует изменения. При замене ключа достаточно `docker compose up -d --force-recreate cabinet-frontend`: новая сборка не нужна.

## Внешний Nginx

Обычно внешний Nginx проксирует `location /` на `http://127.0.0.1:3020` и `/api/` в бот. `/status-api/public` тогда уже попадает в контейнер кабинета — дополнительных изменений не нужно.

Если frontend раздаётся прямо с диска, а не через Nginx контейнера, одного обновления JS недостаточно. Нужно либо перейти на контейнер, либо настроить аналогичный защищённый proxy с ключом, TLS-проверкой и кэшем на веб-сервере. Для контейнера за нестандартным внешним роутингом добавить в HTTPS server блока кабинета:

```nginx
location = /status-api/public {
    proxy_pass http://127.0.0.1:3020;
    proxy_set_header Host $host;
}
```

Перед редактированием внешнего Nginx сделать копию конфигурации; применить только после `sudo nginx -t`.

## Проверка

```bash
docker compose ps cabinet-frontend
curl -fsS http://127.0.0.1:3020/status-api/public
curl -fsS https://xsgvpn.ru/status-api/public
```

Оба запроса должны вернуть JSON с `ok:true`, `servers`, `mobile`. Если внутри работает, а снаружи HTML/404 — проверить внешний маршрут. Если 503 — проверить ключ и доступ контейнера к Uptime; не публиковать env или `nginx -T`, поскольку конфигурация содержит ключ.

Карточка мобильных сетей считает пары «округ + оператор». `up/down` — подтверждённые результаты, `no_bs`, `no_modem`, `modem_unavailable`, `unknown` — без замера, `stale` — устарели. Детализация no_modem уже входит в unknown в агрегате API. Зелёная подпись говорит об успешных выполненных проверках, а не о доступности всей России. Компактная плитка показывает результат и число округов/операторов. По нажатию открывается отдельное окно с таблицей, временем по Москве и причинами отсутствующих замеров; окно закрывается кнопкой или Escape. При running/pending явно показано ожидание новой проверки. Плитки серверов одинаковой высоты: два столбца на телефоне, четыре на большом экране.

## Локальная разработка

В `.env.local` установить `XSG_UPTIME_API_KEY`. Vite читает его только на сервере разработки и проксирует точный путь `/status-api/public`; переменная не экспортируется в JS. Продакшен-кэш и ограничения работают в Nginx, dev proxy нужен только для разработки.
